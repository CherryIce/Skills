# 内置整理模板

仅在新建文档且用户没有提供参考文档时使用 [default-design-index.docx](../assets/default-design-index.docx)。已提供参考文档或正在修改现有文档时，以用户文件为格式依据。不要先要求用户补交参考文档。

## 使用方法

先复制内置文件到本次任务的工作目录，再填充副本，不改写技能中的原始模板。使用 documents 技能建立任务内的模板记录、运行操作标记，并渲染检查最后文档。

内置 DOCX 提供真实的页面与样式定义，而不是仅靠一句“按默认格式”。可根据内容长度正常扩展页数；标题、重复块和段落均可克隆。没有实际内容的可选章节整段移除，剩余一级章节重新连续编号。

所有 `{{字段名}}` 均为待替换槽位。完成后检查正文、页眉页脚和表格，不得留下任何占位符或指向示例节点的链接。模板本身没有真实 Figma 链接，不得把蓝色占位文字当作可点击链接交付。

## 页面和样式

- Letter 纵向，8.5 × 11 英寸；四边距各1英寸；单栏，无装饰线、页眉或页脚。
- 文档标题使用 Word `Title` 样式，22pt、黑色、左对齐；副标题11.5pt黑色。
- 一级标题 `Heading 1` 为13pt黑色，二级标题 `Heading 2` 为11.5pt黑色；页面名称 `Design Page` 为11pt黑色加粗。
- 正文 `Normal` 为11pt、固定17pt行距、段后6pt、左对齐；标题按字号设置充足行高。`Design Detail` 为10.5pt，供简短辅助说明使用；不为压缩页数缩小正文。
- 版本链接使用 `Design Links` 段落样式及蓝色带下划线的 `Hyperlink` 字符样式，保持清楚的分隔和可点击目标。
- 当前资产的文字字体为 Arial Unicode MS。若运行环境缺少可用字形，可仅在工作副本中换用已确认可用的中文字体并重新渲染，不把某个操作系统字体作为安装前提。
- “覆盖与链接核对结果”另起一页；其他章节随内容自然分页。标题和页面名与后文保持，避免标题单独落在页尾。

## 内容槽位

### 开篇与总入口

将 `{{文档标题}}` 换成明确的项目或模块名称，例如“账户模块设计稿目录”；不附加营销口号。开篇一两句说明实际整理的内容范围和阅读方式。

“00 阅读说明与总入口”记录整理日期、范围和可点击总入口。多个 Figma 范围分别列出，保留对应 file key 与节点；不要用整个文件主页替代用户指定的局部范围。

### 功能页面与状态

“01 功能页面与状态”下按设计稿的功能逻辑生成二级标题。克隆以下重复块：

1. `Heading 2` 的 `{{功能分组编号}} {{功能分组名称}}`，每个功能分组一次。
2. `Design Page` 的 `{{页面编号}} {{页面或状态名称}}`，每个真实页面或状态一次。
3. `Design Detail` 的页面说明，简述原稿明确展示的内容；纯目录无需说明时可删除该段。
4. `Design Links` 的版本行：将每个版本名称绑定为指向对应实际画板的超链接。数量和组合取自设计稿，不能固定为三个版本。

同组版本在一行能舒适容纳时并列；太长则分行，不缩小文字。无主题或语言区分时，链接文字可为“打开设计稿”；有差异时写清“中文亮色”“英文暗色”等实际版本。页面序号用于检索，不等同于旧图层编号。

### 开发标注

存在独立开发标注、组件说明或图例时保留“02 开发标注与复用说明”，克隆标注名称、简述和链接块。标注与页面分开计数。没有此类内容时删除整章，不补造文案。

### 覆盖与链接核对结果

最后一章记录核对日期、核对范围、已覆盖的功能页面及状态、实际版本组合和数量、标注数量、链接出现次数与核对结论。若存在未提供版本、隐藏组件状态或尚未核实事项，只写与本次范围有关的实际情况。

结论来自独立设计清单和最终 DOCX 的链接核对。模板的文字槽位不构成通过证据；不因字段叫“核对结论”就自动填“全部通过”。
