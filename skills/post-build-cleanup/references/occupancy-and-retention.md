# 占用、稳定性与混合目录判断

用于常驻进程仍存在、缓存曾被占用/延迟处理、并发项目，或用户明确授权的精确共享 Xcode 缓存。先确认本次授权与目录身份；本参考不扩大清理范围。

## 以路径和实际任务为依据

- 记录候选目录的绝对路径、设备号/inode、用途、大小、检查时间和项目身份。Xcode 项目 DerivedData 读取 `info.plist` 的 `WorkspacePath`，核对实际 workspace；目录名中的 Runner 或应用名前缀不是身份证明。共享 ModuleCache/CompilationCache 等要单独识别类型，不能冒充项目目录。
- 在 macOS 可用进程清单与 `lsof -n -P` 查看打开文件、目录句柄和 `txt` 内存映射；检查错误与权限是否导致清单不完整。结合可执行文件、命令参数、父子进程、工作目录、编译/测试/运行工具和必要的 Xcode 活动状态，判断任务是否与当前候选相关。仅打开源码或工作目录的编辑/工具会话不等于占用构建缓存；关联不明的真实构建/运行任务仍应保留。
- SKAgent/SourceKitService 属于代码分析相关服务；查看它们实际打开的是哪个项目的 `Index.noindex/UniDB/.../*.mdb`，不要按进程名把所有项目都判为占用。同一个 PID 也可能被复用，复查可执行文件、进程启动身份和当前句柄；旧进程退出、另一个进程服务其他 workspace 后，需要重新按目标路径判断。
- Xcode、SKAgent、SourceKitService、XCBBuildService/SWBBuildService 或 LLDB 辅助服务仍存在，不等于正在使用当前缓存。CPU 为零、休眠、累计 CPU 时间不变、只显示欢迎页/停止按钮不可用、LLDB 只有 CLOSED 连接，也都只是辅助证据；不得单独据此判定可删。反过来，LLDB 仍有连接也不能只凭连接数认定正在调试哪个应用，要核对目标与状态。
- 发现目标树中的打开句柄/内存映射，或确认有关联的构建、测试、安装、运行、调试、热重载、索引任务，保留该树中任务依赖的部分。活动索引数据库可能依赖旁边的 DataStore，不要仅留下 `.mdb` 后删除其关联记录。无法证明可拆分时，保留完整索引树。不终止用户进程、不关闭工程、不改变索引或全局设置来制造可删条件。

## 对先前占用或延迟清理的缓存确认稳定

至少取得两次独立观察，结合中间的合理工作间隔，避免把同一份快照或紧邻的重复查询算作长期闲置。正常当前任务独占的临时目录不需要因此创建定时任务。

每次观察记录：

| 记录 | 用途 |
| --- | --- |
| 根目录设备号/inode、规范路径、项目身份 | 检测同名目录替换、路径迁移或任务范围变化 |
| 排序后的相对路径、类型/权限、大小、`mtime_ns`、inode，以及符号链接目标的指纹 | 检测树内新增、替换、写入或重生成；不跟随链接越界扫描 |
| 逻辑大小、分配空间、条目数和最新修改时间 | 解释缓存变化与清理量；单独总大小不构成稳定性证明 |
| 进程启动身份、实际打开路径/映射、关联任务及检查错误 | 区分当前占用、其他项目活动和不可可靠核验 |
| 上次检查时间与观察标识 | 避免重复查询虚增闲置次数 |

两次均无相关占用/任务、指纹稳定且检查完整，才可将这个条件作为清理依据。出现活动、写入、身份变化或检查不完整时，旧闲置证据失效；先核实当前任务与授权，再重新观察。预览后、删除前复查同一组精确路径，变化则停止相关删除。

内存映射数据库可能在文件大小和修改时间看似稳定时被更新；**实际句柄、映射或已确认的任务优先于稳定指纹**。仍在使用的数据库始终排除删除；它自身合法更新不应被误报为清理损坏其他保留产物，但必须单独记录，不能声称其内容校验一致。

## 拆分缓存与保留产物

- 先完整检查候选树，而非仅看顶层名字。`Index.noindex` 下也可能存在 `Build/Products`，其中有 framework、头文件或其他依赖/产物。优先保留整个 Products 子树，以及 app、framework/xcframework、dSYM、归档、安装包、签名资料、日志、测试结果、截图和所需证据。
- 使用独立保留清单；只选择已证明是生成数据的精确兄弟目录，例如闲置索引的 DataStore、UniDB、生成构建描述，以及不混入保留项的 `Build/Intermediates.noindex`。名称只是线索，不构成自动删除白名单。仍活动的索引不能照搬这个拆分示例。
- 索引的 `.mdb`、XCBuildData 的 `build.db` 可以是可重建的工具状态；业务数据库、依赖、手写源文件不能因扩展名或位于 build 中被视为缓存。需要从具体目录结构、工具输出和项目归属证明用途。
- 对项目内目录使用技能脚本预览/执行；遇到产物保护拒绝，缩小到安全兄弟目录，并用 `--keep` 表达其余保留项。脚本只接受目录，不把 `build-description.json` 等单个文件当作 `--cache` 传入；没有另行核验的精确文件实现时，保留文件并说明。它也不检查进程、文件写入或所有自定义产物类型，不能替代上述调查。共享 Xcode 缓存仅在单独明确授权后，使用只允许那些精确路径的独立实现；不要伪造 `--project`。
- 清理前后核对源码/未提交和未跟踪内容、暂存状态、依赖与保留产物。可用内容校验和及稳定的目录清单；对明确仍活跃且完全排除删除的缓存，记录占用和排除证据，不将其合法变化混入产物不变断言。保留日志及必要诊断证据，清理失败不应抹掉原验证结论。

## 结论与结束条件

分开报告“确认删除的缓存”“仍在使用的缓存”“主动保留的产物/依赖”和“无法可靠检查的范围”。缓存根目录只剩 Products 时，说明可删部分已清理并给出保留量，不声称整个根目录消失。

用户未要求自动跟进时，不创建监测或安排以后清理。用户要求停用时保持停用；若此前已授权跟进且本次范围已处理完、余项均应保留或用户要求结束，则停用对应跟进，不继续接管其他任务新生成的数据。此规则不要求修改任何无关自动任务。
