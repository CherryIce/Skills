# 构建验证后清理

把清理作为构建验证任务的收尾步骤。用户已授权在验证结束后清除无需保留的构建数据；明确属于该范围的清理直接执行，无需重复询问。遵从用户当前要求，例如保留构建目录、继续热重载、交付安装包或留待调试。

## 构建前记录范围

- 确定实际项目/应用根目录和本次使用的输出路径。多应用仓库只记录当前应用；不要递归发现并清除整个仓库的所有 `build`。
- 尽量让本次输出进入项目专用目录，例如 Xcode 的 `-derivedDataPath "$PROJECT/.codex-build/DerivedData"`。仅在构建工具支持且不改变验证目标时调整输出路径；不要为清理修改业务代码或提交项目配置。
- 对已有输出目录记录其用途及是否被其他任务使用。名称含 `build`、Git 忽略或磁盘占用大，都不能单独证明它可删除。

## 在验证结束时执行

1. 等待本次构建、测试和运行检查结束，完成必要的后续分析。先提取并保留验证结论、关键日志、截图、测试报告及失败诊断证据；不要把“构建成功”表述成“运行验证成功”。
2. 把需要交付的 APK/AAB/IPA、归档、符号文件等复制到用户要求的持久位置，检查副本存在且完整，再考虑清理原缓存。项目约定的发布/交付目录始终保留；输出文件有保留价值时，不能因为可再生就直接删除。若不宜移动产物，保留所在子树，仅清理确定可删的兄弟目录。
3. 确认没有仍在使用目标路径的构建、测试、安装、调试、热重载或开发服务。只停止本任务启动且已用完的进程；其他会话还在使用、所有权不明或用户要求继续运行时，跳过相关目录并说明。不要终止共享守护进程来强行清理。
4. 对本次确认可丢弃的精确路径，先预览，再实际删除。正常收尾时必须完成实际清理，不能仅报告预览。使用本技能的 [scripts/cleanup_build_data.py](scripts/cleanup_build_data.py)，它默认仅预览，`--apply` 才删除；无需把预览作为用户审批流程。
5. 检查目标已消失，记录实际删除成功的目录及其清理前占用；不要将目录大小估算表述成精确的可用磁盘空间增量。失败时记录错误，保持真实验证结论，不为清理再次构建。构建失败且已结束诊断时也清理可丢弃数据；仍待分析或用户要求保留现场时保留所需部分并说明。

```sh
python3 "$SKILL_DIR/scripts/cleanup_build_data.py" \
  --project "$PROJECT" \
  --cache "$PROJECT/.codex-build" \
  --cache "$PROJECT/build" \
  --keep "$PROJECT/outputs"

# 确认预览仅包含本次可丢弃的路径后，使用相同参数加 --apply。
```

`SKILL_DIR` 是当前 `SKILL.md` 所在目录；`PROJECT` 是实际应用根目录。替换示例中的路径，仅传入实际使用过的缓存；不需要创建示例目录。脚本拒绝非白名单路径、项目外路径、符号链接目标或祖先、受保护路径、包含 Git 跟踪文件/嵌套仓库的目录，以及与 `--keep` 重叠的目标。整批先检查再删除；遭拒绝时缩小到安全子目录，不能绕过检查改用宽泛删除。

## 常见项目的选择依据

| 项目 | 仅在本次用过且确认可丢弃时清理 | 保留 |
| --- | --- | --- |
| iOS/Xcode | 项目内专用 DerivedData、`.derivedData`、临时编译/链接和索引数据 | 交付 `.xcarchive`、dSYM、IPA，仍需分析的 `.xcresult`，签名资料，Pods、SwiftPM 依赖 |
| Flutter | 当前应用 `build/`、`.dart_tool/flutter_build/` | `.dart_tool/package_config.json` 等包解析信息、`.fvm`、SDK、依赖缓存、需交付安装包 |
| Android/Gradle | 当前模块 `build/`，确认闲置的项目内 `.gradle/` 构建状态 | `~/.gradle`、Wrapper、SDK/NDK、签名及 keystore、需交付 APK/AAB |
| Web | `.next/cache/`、`node_modules/.cache/` | `node_modules`、包管理器缓存、锁文件、用户要运行/部署的站点产物 |
| Rust/SwiftPM/CMake 等 | 任务明确使用过的 `target/` 编译输出、`.build/` 编译子树、专用 `cmake-build-*` 或 `.codex-build/` | Cargo/SwiftPM 下载依赖、手写源码、配置及待交付二进制 |

## 边界

- 仅删除已确认属于当前任务、可重新生成且无需保留的数据。保护源码、未提交修改、资源、数据库、签名/证书、配置、锁文件、持久产物和必要证据；依赖目录及共享缓存默认保留。
- 不运行 `git clean -fdx`、全局 `rm -rf`、Gradle/pub/npm/pip 全局缓存清理、Docker prune、模拟器数据擦除或整机 DerivedData 清空。`flutter clean` 等命令可能同时清除范围外内容，应优先删除已确认的精确目录。
- 共享的 `~/Library/Developer/Xcode/DerivedData` 不交给脚本处理。今后优先使用项目专用输出路径；已有共享路径身份不明时跳过，不能靠项目前缀猜测。非白名单工具的缓存先从实际命令/配置证明输出路径，再清理专用输出；不确定时保留并给出理由。
- 本技能是 Codex 在任务中的收尾流程，不是后台守护进程；不影响用户在 Codex 之外自行启动的构建，也不追溯清理所有历史项目。

最终回复简述验证结论、清理目录和约清理量；若有保留/失败，说明实际原因即可。没有产生构建数据时无需制造清理步骤。
