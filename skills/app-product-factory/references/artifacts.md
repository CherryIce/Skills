# Persistent artifacts

Reuse existing repository documentation conventions. When none exist, place product-factory documents under `docs/product/` and release evidence under `docs/release/`. Create only the files needed by the selected run scope.

## Product intake

Record target user, problem, context, frequency, launch region, business model, platforms, required permissions, data sensitivity, account/backend needs, supplied references, constraints, assumptions, and requested stopping point.

## Market evidence

Use a source table with URL, publisher, access date, direct observation, inferred implication, and confidence. Follow it with a competitor matrix and repeated user-pain themes. Keep facts and inference distinct.

## Product brief and PRD

Include product thesis, non-goals, core loop, screen/state inventory, domain model, privacy/payment/account choices, functional requirements, acceptance criteria, originality decisions, and deferred risks.

## Differentiation report

Include hard-failure scan, scored dimensions with evidence, verdict, competitor-independent rationale, and at most three revision directions when weak.

## Evidence register

For every claim, record evidence type, command/device/build, date, result, limitations, and artifact location. Never label unperformed evidence as passing.

## Review reports

Functional and Store Reviewer reports contain findings first, severity, evidence, acceptance tests, untested layers, and verdict. Store findings also cite current official requirements.

## Gap backlog

Each item contains source finding, user value, policy/differentiation effect, scope, dependencies, acceptance criteria, validation layer, estimated cost, and priority. Select coherent slices, not isolated feature-count additions.

## Release-candidate report

Record branch and SHA, dirty state, Flutter/Xcode versions, flavor and entry point, checks run, simulator/device coverage, archive identifiers and contents, public URLs, metadata status, upload/TestFlight/App Review state, and unresolved external actions.
